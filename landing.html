契约文件示例

# Module: payment > 支付模块 ## Public API ### Functions async create_order(amount, currency) → Order refund(order_id, reason, partial) → RefundResult ## Dependencies - database — 订单持久化 - gateway — 支付网关 ## Side Effects - [x] Database writes - [x] Network requests ## Files - src/payment/service.py - src/payment/models.py

AI 看到这份 500 tokens 的契约，就完全理解支付模块的边界和能力，不需要去读 300 行实现代码。

安装 & 使用

$ pip install ai-context $ cd your-project $ ai-context init # 初始化 .ai/ 目录 $ ai-context scan # 扫描代码生成契约 $ ai-context status # 查看 token 节省效果

生成的项目结构

your-project/ ├── .ai/ # AI 上下文层（提交到 Git） │ ├── PROJECT.md # 项目总览，AI 第一个读 │ ├── GUIDE.md # AI 开发规范 │ └── contracts/ │ ├── auth.contract.md │ ├── payment.contract.md │ └── database.contract.md ├── src/ # 你的代码（不变） └── ...

完整命令

命令作用
ai-context init初始化 .ai/ 目录结构
ai-context scan扫描项目，自动生成所有契约
ai-context gen <name>为新模块创建契约骨架
ai-context check检查契约是否与代码同步
ai-context status查看 Token 消耗对比报告

常见问题

需要手动维护契约文件吗？
基本不需要。scan 自动从代码提取 API。改了接口跑一次 scan 就行。
契约文件应该提交 Git 吗？
应该。团队共享才能保证所有人的 AI 上下文一致。
支持哪些编程语言？
当前 Python（AST 解析）和 TypeScript/JavaScript。更多语言计划中。
和其它工具有什么区别？
我们解决的是"高层上下文策略"——让 AI 知道该读什么、不该读什么。不是缓存优化或压缩。
